# NexusMusic Fusion — Vercel sin claves de YouTube

1. Extrae el ZIP y copia los archivos a la raíz de tu proyecto Vercel. Fusiona `assets/` con tu carpeta original: las imágenes y capturas originales no estaban adjuntas.
2. Framework Preset: Other; sin build command ni output directory personalizados. Conserva `api/music-search.js` en esa ruta. No se necesita `YOUTUBE_API_KEY`, ni una clave de Audius para las consultas públicas. Publica de nuevo.
3. Abre `/api/music-search?q=lofi` (debe devolver `items`) y `/listen?web=1`. Busca una canción y pulsa Escuchar. El catálogo es Audius: no equivale al catálogo de YouTube y solo se muestran pistas públicas marcadas como reproducibles. El servicio externo puede limitar peticiones o restringir pistas.
4. Discord: los enlaces existentes `/listen?v=ID_DE_YOUTUBE&web=1` siguen funcionando cuando YouTube permite la inserción. Puedes agregar `title` y `artist` codificados con URLSearchParams para mostrar metadatos incluso si oEmbed no responde. Pega enlaces de YouTube en el buscador o envía enlaces HTTPS a archivos de audio de `cdn.discordapp.com/attachments/...` o `media.discordapp.net/attachments/...` usando `/listen?web=1&audio=URL_CODIFICADA`. También se acepta `url` y `videoId`. Los enlaces de archivos pueden caducar: no se renuevan sin acceso al origen. No se conecta al bot ni a canales de Discord; no se adjuntó su código. No se extrae audio de YouTube ni se evaden restricciones.
5. En el caso de un video bloqueado, se ofrece abrir el original y, cuando hay título, buscar otra versión en Audius. El resultado no es necesariamente la misma grabación. No se necesita API key para el iframe oficial.
6. Biblioteca y playlists conservan sus claves localStorage previas si mantienes dominio y navegador. No borres datos del sitio al actualizar. Los enlaces de Discord se guardan en el navegador al añadirlos a la cola o biblioteca; evita guardar enlaces privados. Para producción revisa privacidad y añade rate limiting en Vercel.

Pruebas: sintaxis JavaScript y pruebas unitarias simuladas de la función serverless; no se verificaron peticiones reales a Audius/YouTube/Discord porque el entorno no resolvió DNS externo y Chromium bloqueó la navegación local. El diseño y reproducción final deben comprobarse tras desplegar. Se conserva la lógica anterior de biblioteca y navegación; el reproductor y el endpoint se han adaptado a múltiples fuentes.
